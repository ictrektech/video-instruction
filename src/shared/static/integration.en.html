Endpoints and identity

In the VOS Docker network use http://video-structure-detect:8910 for detection and http://video-structure:8911 for structure/description. External host ports default to http://<HOST>:48910 / :48911 and can be changed during installation. Do not assume a fixed Docker bridge IP. The service itself has no user/API-key authentication; direct ports require a trusted network. VOS gateway access follows platform policy.

VOS proxy prefixes are /api/com.ictrek.video-structure/detect and /api/com.ictrek.video-structure/structure. Append the API paths below. Each service exposes GET /api/health, /docs and /openapi.json. Detection Swagger · Structure Swagger. Complete field constraints are in the installed service's OpenAPI schemas.

Health returns {"code":0,"msg":"…","data":{"status":"ok","service":"scene-detection"}} (or service structure). Health only establishes API availability, not worker completion or model availability. Configure caller base URLs explicitly; declaring an application dependency does not inject them.

Detection request and result

POST /api/v1/scenes/detect is synchronous. POST /api/v2/scenes/detect/jobs accepts the same JSON asynchronously. Required video_path:string is an HTTP(S) video URL or a path readable inside the server container. Optional nullable fields: threshold:number, max_scenes:integer, scale_width:integer, decode_threads:integer. Omitted values use server policy. Zero means unlimited scenes, no scaling or automatic decode threads respectively for the last three fields; it is not equivalent to omission.

Synchronous success is {code:0,msg:string,data:DetectResult}. DetectResult contains metadata:{fps:number,total_frames:integer,duration:number,width:integer,height:integer}, policy:{threshold:number,min_scene_len_sec:number,max_scene_count:integer}, scenes:SceneBoundary[], warnings:Warning[] and elapsed_sec:number. Each boundary has scene_index:integer,start_frame:integer,end_frame:integer,start_time:number,end_time:number. Times are seconds; end_frame is inclusive, while end_time is the boundary after the last frame: (end_frame+1)/fps. A warning has string code,message,scope,target_id. Read actual policy rather than assuming a fixed threshold; duration-based defaults vary.

Submission, polling and reuse

Detection, structure and describe submissions return {"code":0,"msg":"…","data":{"job_id":"…","status":"queued","poll_url":"/api/…/jobs/…"}}. Resolve poll_url against that service's base URL, preserving a VOS proxy prefix when used. Poll GET /api/v2/scenes/detect/jobs/{job_id}, GET /api/v2/video/structure/jobs/{job_id} or GET /api/v2/video/describe/jobs/{job_id}, normally every 2–5 seconds with a bounded deadline.

Common data fields: job_id:string,type:string,status:queued|running|succeeded|failed,created_at:integer|null,started_at:integer|null,finished_at:integer|null,attempt:integer,progress:string|null,result:object|null,error:JobError|null. Timestamps are Unix seconds. JobError has nullable code:string,message:string,detail:object|string. Historical detail strings remain readable. Detection results contain metadata, policy, scenes and warnings (no synchronous elapsed_sec). Structure/description result shapes are documented below. Failed jobs can still return HTTP 200 with outer code 0; inspect status/error.

For the same video_hash and job type, queued/running jobs are reused. URL hashes use the token-redacted URL, not video contents; local files use sampled MD5. Keep video URLs stable, but replace the URL when content changes. Changing non-redacted signature parameters changes identity. Description reuse uses structure_job_id. The API has no general cancel or retry endpoint: DELETE below releases finished structure artifacts, not an active calculation.

Structure request, result and artifact release

POST /api/v2/video/structure/jobs: required video_path:string; provide either nonempty scenes:SceneBoundaryInput[] or detect_job_id:string. Use the same video as detection. A referenced detection must finish successfully before structure can use its result. If both are provided, the referenced job is still checked; choose one mode. Boundary input requires integer start_frame/end_frame; scene_index defaults to 0 and start_time/end_time to 0.0. Optional frame_grid:boolean=true,grid_rows:integer=3,grid_cols:integer=3.

Successful structure result: video_hash:string,metadata:VideoMetadata,staging_dir:string,scenes:Scene[],warnings:Warning[],stage_timings:object<string,number>,elapsed_sec:number. VideoMetadata contains video_path, fps, duration, width, height, codec, bitrate, has_audio and total_frames. Scene contains scene_id, scene_index, start_time, end_time, start_frame, end_frame and nullable grid_image. Warning additionally supports structured detail. Paths are container paths, not downloadable URLs.

Structure polling adds released:boolean and nullable artifact:{describe_status:none|pending|succeeded|failed,total_bytes:integer,files:[{path:string,size:integer}]}. Artifact is null until succeeded, during description freezing, or after release. Download only after artifact is available.

GET /api/v2/video/structure/jobs/{job_id}/artifact returns 200 application/x-tar, with X-Artifact-Describe-Status: none|succeeded|failed. This is a binary download, not JSON or a polling request. Errors return JSON with real HTTP 404 (unknown/wrong-type job), 409 (not ready/description pending), or 410 (staging gone). Tar contains manifest.json, grids/*.jpg and optional descriptions.json; metadata.json is not separately packaged.

DELETE /api/v2/video/structure/jobs/{job_id} releases staging after download and returns {"code":0,"msg":"…","data":{"job_id":"…","released":true}}. Releasing an already released terminal job is idempotent. Queued/running jobs return 409/code10002. Verify the downloaded tar before releasing; released artifacts cannot be downloaded again.

Vision descriptions and V-Scheduler

POST /api/v2/video/describe/jobs: required structure_job_id:string of a successful, unreleased structure job; optional force:boolean=false and model_cfg:object|null. force requests fresh descriptions rather than keeping existing ones. Every model_cfg field is optional/nullable and falls back to server configuration: base_url:string,api_key:string,model_name:string,max_concurrency:integer,request_timeout:integer (seconds). Defaults in VOS are http://v-scheduler:8080/v1, empty key, configured vision model, concurrency20 and timeout120; standalone settings can differ.

Copy the complete vision-capable model ID from V-Scheduler. For a private model, api_key must be a valid V-Scheduler access key; the upstream vendor key belongs in V-Scheduler provider settings. Public model access follows V-Scheduler public-model policy. An arbitrary chat model without image support cannot describe grids.

Description result contains structure_job_id:string,video_hash:string,descriptions:Description[],warnings:Warning[],status:completed|partial. Each Description has scene_index:integer,grid_image:string,description:string,status:ok|skipped|failed,error:string|null. A succeeded job can be partial: inspect each scene and warnings. Job-level error codes include SCENE_DETECT_ERROR, STRUCTURE_ERROR, DESCRIBE_ERROR and DESCRIBE_MODEL_NOT_FOUND. Description error/warning detail can include model, base_url, status_code, upstream_code, upstream_message, request_id, failed_scenes and total_scenes. Do not parse message text to determine the failing model.

Errors, validation and safe retries

Normal business errors return HTTP200 {code:integer,msg:string,data:null}, while success uses code0. Missing/invalid JSON fields use FastAPI 422 {detail:[...]}; unexpected errors use HTTP500. Artifact/release routes also use real HTTP errors. Check HTTP status and Content-Type, then envelope code, then job status and individual scene results. Never treat an HTTP200 failed job as success.

Business codes: 10001 missing object/staging; 10002 unsupported or not-ready operation; 10004 invalid argument; 70101 missing local video; 70201 unknown job; 10000 downstream service failure; 99999 unexpected failure. Correct 422/invalid fields instead of retrying unchanged. For 409 poll status before downloading again; 410 requires regenerating artifacts. After submission timeouts reconcile using the returned job ID when available; pending-job reuse is not a permanent idempotency guarantee.

Complete detection → structure → download workflow

export DETECT='http://video-structure-detect:8910'
export STRUCTURE='http://video-structure:8911'
# VIDEO_URL must be reachable by both workers and remain valid through the job
curl --fail-with-body "$DETECT/api/v2/scenes/detect/jobs" \
  -H 'Content-Type: application/json' -d '{"video_path":"http://media-service/video.mp4"}'
# Save data.job_id as DETECT_ID; poll until data.status=succeeded
curl --fail-with-body "$DETECT/api/v2/scenes/detect/jobs/$DETECT_ID"
curl --fail-with-body "$STRUCTURE/api/v2/video/structure/jobs" \
  -H 'Content-Type: application/json' \
  -d "{\"video_path\":\"http://media-service/video.mp4\",\"detect_job_id\":\"$DETECT_ID\"}"
# Save data.job_id as STRUCTURE_ID; poll until succeeded and artifact is non-null
curl --fail-with-body "$STRUCTURE/api/v2/video/structure/jobs/$STRUCTURE_ID"
curl --fail-with-body -o structure.tar "$STRUCTURE/api/v2/video/structure/jobs/$STRUCTURE_ID/artifact"
# Verify download and extract before releasing
curl --fail-with-body -X DELETE "$STRUCTURE/api/v2/video/structure/jobs/$STRUCTURE_ID"

Video access, storage and configuration

Prefer HTTP(S) video streams reachable from both server containers. localhost points to the container itself. Return actual video bytes, preferably supporting Range; URL validity must include queueing and processing. An absolute path must exist inside both containers; relative paths resolve below DATA_BASE_PATH (VOS default /photos). URL submission does not preflight the media: read failures appear in job errors.

VOS detection and structure containers must share jobs/queue SQLite and staging volumes on the same host. They do not own the original video; callers own downloads. VOS defaults: STAGING_BASE_PATH=/data/video-structure-cache, STAGING_TTL_SEC=604800 (standalone code default21600), JOB_TTL_DAYS=7 (0 disables cleanup), VIDEO_DETECT_SCALE_WIDTH=640, VIDEO_DECODE_THREADS=0. Worker concurrency is the compose CLI --workers 2; the HUEY_WORKERS environment variable does not currently override it. Describe defaults can be changed with LLM_BASE_URL, LLM_API_KEY, LLM_MODEL_NAME, LLM_MAX_CONCURRENCY and LLM_REQUEST_TIMEOUT. Keep keys out of logs and shared documents.
